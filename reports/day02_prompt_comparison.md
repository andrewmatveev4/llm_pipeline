# День 2. Сравнение промптов

## Результат
3 варианта промпта, лесенкой (каждый = предыдущий + одна добавка), 5 текстов × 3 повтора = 45 вызовов.

| Вариант | Состав | Прошло | Разброс длины summary |
|---|---|---|---|
| v1_baseline | база | 12/15 | 2.0 слова |
| v2_limits | + лимиты длины | 15/15 | 0.2 |
| v3_example | + лимиты + пример | 15/15 | 0.4 |

Невалидный JSON: 0 из 45. Инъекция в 05_injection не сработала ни разу.

**Выбран v2_limits:** качество как у v3, промпт короче (86 слов против 155), вызов дешевле.

## Как мерили
- Аккуратность: 6 автоматических проверок (ключи, summary ≤ 25 слов, ровно 3 пункта,
  пункт ≤ 12 слов, ответ ≤ 3 предложений, язык ответа = язык входа). Ответ прошёл = все зелёные.
- Стабильность: max - min длины summary на 3 повторах одного текста, усреднено по текстам.
- Сырые результаты в outputs/day02_comparison.json (кэш, повторный запуск не тратит деньги).

## Выводы
- Все 3 провала v1 на длинном тексте (04_long), все по длине key points, 3 из 3 повторов:
  дефект промпта, не случайность. Без лимитов модель растягивает ответ под объём входа.
- Числовые лимиты дали +3 прохода и в 10 раз меньший разброс. Пример (few-shot) поверх
  лимитов ничего не добавил; разница 0.2 и 0.4 в пределах шума на 3 повторах.
- Различие между промптами видно только на граничных текстах: на коротких все варианты равны.

## Отступления от задания
1. Сравнение автоматическими проверками и повторами, а не просмотром ответов глазами
2. В базовом промпте убраны лимиты дня 1, чтобы v1 был чистой контрольной группой
3. Лимиты в словах, не в символах; подсчёт предложений грубый (т.е., 3.5)
4. Проверка языка через наличие кириллицы: только RU/не-RU; пустой вход даёт ложный ✅ (отсекать в день 5)
5. В эксперименте ловится json.JSONDecodeError, чтобы один плохой ответ не обнулил 45 вызовов
6. Путь результата в main.py с номером дня захардкожен; вынести в аргумент (дни 6–7)
