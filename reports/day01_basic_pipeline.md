# День 1. Базовый LLM pipeline

## Результат
- Пайплайн: текст -> промпт -> LLM -> JSON -> dict -> outputs/day01_results.json
- 3 тестовых текста (RU техвопрос, RU новость, EN запрос): у всех есть summary, 3 key_points, response
- Язык ответа совпадает с языком входа (после 2 итераций промпта)
- 2 юнит-теста с фейковым клиентом, без сети и без .env, 0.28 с

## Структура
- llm_pipeline/llm_client.py: get_client, call_llm (только вызов API)
- llm_pipeline/prompts.py: SYSTEM_PROMPT, USER_TEMPLATE, build_user_prompt
- llm_pipeline/pipeline.py: process_text
- main.py: чтение sample_inputs/*.txt, прогон, сохранение JSON
- tests/test_pipeline.py

## Отступления от задания
1. Модель gpt-4.1-mini (не reasoning, поддерживает temperature, дешёвая); задаётся в .env
2. Пакет под pyproject + pip install -e вместо плоских файлов; process_text в pipeline.py, main.py только запуск
3. Chat Completions вместо Responses API: формат совместим с другими провайдерами
4. Промпты на английском: на русских инструкциях модель отвечала по-русски на английский текст
5. Плохой JSON и пустой ответ сознательно не обрабатываются (день 5); ограничение зафиксировано тестом

## Выводы
- Модель следует всему контексту, а не одной строке правила: пример ответа и язык инструкций перевешивают явное указание
- Ответ модели всегда строка; JSON внутри строки надо парсить, и парсинг может упасть
- Результат недетерминирован даже при temperature=0.2: проверка "по равенству" невозможна, тестируется своя логика через фейк
