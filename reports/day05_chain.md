# День 5. Multi-step LLM chain

## Результат
- Цепочка из 5 шагов, порядок задан одним списком STEPS в llm_pipeline/chain.py:
  extract_meaning -> classify_request -> build_fields -> write_answer -> self_check
- Состояние ChainState едет через все шаги, каждый шаг дописывает своё поле
- run_chain не падает на сбое модели: записывает failed_step и error, собранные шаги сохраняются
- Логи: INFO на старт и результат каждого шага, выбранный маршрут и вердикт self-check;
  DEBUG время и токены каждого вызова; логи библиотек приглушены до WARNING.
  Полный лог прогона: outputs/day05_chain.log
- 10 текстов: 10/10 прошли весь цикл, ~11 с на текст, 50 вызовов модели
- Тестов: 24, фейк модели отвечает по system-промпту, а не по порядку вызовов

## Как шаги используют друг друга
| Шаг | Получает | Отдаёт |
|---|---|---|
| extract_meaning | текст | summary, 3 мысли, язык |
| classify_request | текст, summary, язык | категория, intent, тональность |
| build_fields | текст, шаги 1–2 | продукт, проблема, действие, срочность, факты, чего не хватает |
| write_answer | текст, шаги 1–3, маршрут по категории | текст ответа |
| self_check | текст, факты шага 3, ответ | противоречия, потерянные детали; вердикт считает код |

## Выводы
- Язык определяется один раз в шаге 1 и передаётся дальше как команда: intent, поля и ответ
  на языке текста. Вчерашний сбой (испанский intent заразил ответ) в этом прогоне не повторился
  (один прогон, гарантии нет)
- Правило про missing_info не работало, пока образец в шаблоне JSON говорил «if any».
  После выравнивания образца с правилом шаг стал выдавать «номер заказа». Модель следует
  образцу сильнее, чем правилу (как в день 1 с языком)
- Судья проверен на 3 подложенных ответах (всё учтено / противоречие / потерян возврат):
  3 верных вердикта из 3, на хорошем ответе ложной тревоги нет
- На реальном прогоне судья строгий: 7 из 10 на проверку, большинство находок придирки
  (низкая precision). Поймал реальную ошибку: на 09_support_en ответ предлагал переустановку,
  хотя клиент написал, что она не помогла
- Судья пропустил выдуманное обещание скидки в 08_sales в двух прогонах: он проверяет
  противоречия с сообщением клиента, но не проверяет, подкреплены ли утверждения ответа.
  Это задача источника знаний (RAG), а не промпта
- Судья конфликтует с защитой от инъекций: на 05_injection правильный отказ записан как
  «противоречие» и «потеря детали: write a poem». Судье нужна категория запроса
- Маршрут other не отказывает, если текст выглядит безобидно: на 02_news дан полный пересказ новости
- Вердикт self-check считает код по находкам судьи, а не сама модель
